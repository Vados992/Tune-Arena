# Tune Arena — Telegram Mini App

Подготовлено 11 ноября 2026. Автор: Vadym Tsinderhoz.

## Готово в коде

- Официальный Telegram WebApp SDK, ready/expand и кнопка «Назад». Обычный браузер продолжает показывать web-приложение.
- POST `/api/auth/telegram/mini`: проверка HMAC-SHA-256 по `TELEGRAM_BOT_TOKEN`, возраста запуска (5 минут), будущей даты (допуск 30 секунд), дубликатов полей, размера и числового Telegram user ID.
- Сеанс создаётся только для подписанной identity. Уже открытый аккаунт другого пользователя не привязывается к новой Telegram identity. Имя, ник и client-side admin-флаг не предоставляют полномочий.
- Подписанный запуск расходуется в одной D1-транзакции с созданием identity/сеанса. Использованный запуск не создаёт новые сеансы в другом браузере. Откат не оставляет расходованный маркер.
- Действительный существующий сеанс может продолжать работу после истечения возраста launch data, если подпись и identity совпадают; просроченный запуск сам по себе новый сеанс не создаёт.
- `TUNE_ADMIN_TELEGRAM_IDS` — до 20 числовых ID через запятую. Старый `TUNE_ADMIN_TELEGRAM_ID` поддерживается. Некорректный список не предоставляет доступ.
- После удаления аккаунта runtime не выполняет автоматическую повторную регистрацию на странице подтверждения удаления.
- Настройка кнопки «Открыть Tune Arena» скриптом `web/scripts/configure-telegram.mjs`.

Обычный browser-вход через Telegram OIDC сохранён. Для входа непосредственно внутри Mini App достаточно bot token; OIDC credentials — отдельная настройка для входа из обычного браузера.

## Действия в аккаунтах владельца

1. Авторизоваться в Cloudflare на доверенном компьютере: `cd web`, `npx wrangler login`.
2. Создать D1 и R2 согласно [DEPLOYMENT_RU.md](DEPLOYMENT_RU.md). Задать `TUNE_D1_DATABASE_ID`, `TUNE_R2_BUCKET_NAME`, `TUNE_APP_ORIGIN` и `TUNE_ADMIN_TELEGRAM_IDS`. Последние — реальные подтверждённые ID владельца и коллеги; в репозитории они не назначены.
3. Создать бота у официального [BotFather](https://t.me/BotFather), если его ещё нет. Токен сохранить в защищённом хранилище, не в Git, переписке или frontend-коде.
4. Собрать `npm ci && npm run build`, затем `npm run deploy:prepare`, `npm run db:remote`, `npm run deploy`.
5. Установить токен Worker-secret командой `npx wrangler secret put TELEGRAM_BOT_TOKEN --name tune-arena` (указать своё имя Worker, если изменено). Ввести токен интерактивно. Затем подтвердить открытие HTTPS-адреса.
6. В BotFather выбрать своего бота, настроить Main Mini App / Menu Button и указать HTTPS-адрес приложения. Альтернатива для menu button: задать bot token и `TUNE_APP_ORIGIN` в защищённой среде и выполнить `node scripts/configure-telegram.mjs` из `web/`. Скрипт меняет меню существующего бота; бота он не создаёт.
7. Проверить вход через кнопку бота с двух аккаунтов: владельца и обычного участника. Админка — `/admin`. Доступ к GitHub не заменяет Telegram allowlist.

Cloudflare/bot credentials отсутствуют в коде. Пока вход в аккаунт Cloudflare и реальный bot token не настроены, Worker, новые D1/R2 и Telegram-кнопка не считаются опубликованными этим изменением. Hosted Sites v33 — отдельное размещение, автоматически этим коммитом не обновляется.

## Приёмка

Автоматические тесты проверяют подписи, подмены, сроки, лимиты, replay, параллельные запросы, откат транзакции, нескольких владельцев, отказ обычному участнику, отзыв доступа после удаления; клиент — один handshake в StrictMode, fallback браузера, ошибки/повтор, ready/expand/back и запрет повторной регистрации после удаления. Общие тесты продолжают проверять загрузку аватара/машины и голосование.

После реального подключения обязательны тесты Telegram на iOS/Android: первая регистрация, повторный вход, переключение аккаунтов, загрузка из галереи и камера, лайк/Турбо, кнопка «Назад», `/admin` владельца и отказ обычному участнику. Эти физические проверки не подменяются автоматическими тестами.

Официальная спецификация: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
