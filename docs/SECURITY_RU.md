# Роли и безопасность

Серверная проверка роли требуется и для `/admin`, и для административных API. Наличие адреса или пункта меню не даёт прав. Премиум не является административной ролью.

## Самостоятельный сервер

По умолчанию `TRUST_SITE_AUTH=0`: произвольные `oai-authenticated-*` заголовки не авторизуют пользователя. Используются серверные email/Telegram identities и непрозрачные сеансы с HttpOnly cookie. Администратор сопоставляется с `TUNE_ADMIN_EMAIL` по идентичности email, подтверждённой провайдером, а не по введённому никнейму.

`TRUST_SITE_AUTH=1` предназначен только для развёртывания за доверенным шлюзом Sites, который проверяет/заменяет соответствующие заголовки. На публичном standalone Worker этот режим включать нельзя.

Локальный демовход требует одновременно `ENVIRONMENT=development`, `LOCAL_DEV_AUTH=1` и origin localhost/127.0.0.1. Локальные админские права дополнительно требуют `LOCAL_DEV_ADMIN=1` и демо-identity. Production-конфиг не включает эти настройки. Проверены отрицательные сценарии: поддельный platform identity, отсутствие сеанса, production + demo flags.

## Клиенты

Desktop: sandbox, contextIsolation и webSecurity включены; nodeIntegration выключен. У удалённой страницы нет preload/IPC API. Настройки доступны только отдельному локальному окну с проверкой отправителя IPC. Камера ограничена origin выбранного сервера и только видео, после явного диалога. Внешние file/javascript URL блокируются.

iOS: WKWebView без native JavaScript bridge. Камера — только основной фрейм выбранного HTTPS-сервера, с системным запросом. Android: WebView без addJavascriptInterface; mixed content и cleartext запрещены, запросы камеры ограничены origin и CAMERA permission, audio capture запрещён.

Email-ссылки привязаны к инициировавшему браузеру. Native-клиенты имеют отдельное поле «Открыть ссылку для входа»: вставка ссылки в тот же клиент сохраняет этот контекст. Ссылка не сохраняется в настройках и не логируется.

Сертификаты подписи, provider API keys, конфигурация владельца и пользовательские базы не входят в git. Проверки в этом репозитории не являются независимым security-аудитом или подтверждением защиты от всех ботов.
