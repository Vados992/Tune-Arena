Тестовые Android-файлы и SHA-256 находятся в [`downloads/android/`](../downloads/android/README.md). APK подписан тестовым debug-ключом. Проверка установки, камеры и реального входа на Android-устройстве пока не выполнена.

API-проверки покрывают: игнорирование поддельных платформенных заголовков на самостоятельном сервере; запрет DEMO-входа в production; вход/выход и роль администратора; запрет admin для обычного участника; смену лайка на дизлайк; запрет комментариев; границы времени и повторы голосования; автоматический итог и повторное объявление; отсутствие победителя при одних дизлайках; загрузку; cookie-рефералы, 3 дня новичку и 30 дней за 3 активных приглашённых; однократность и конкурентные повторы начислений. SQL-проверки используют SQLite; облачный D1 и production-провайдеры требуют отдельной эксплуатационной проверки.

Android lint оставляет предупреждения о необходимом JavaScript в WebView, форме launcher-иконок и новых правилах резервирования. Ошибок lint нет. Приложение не предоставляет JavaScript доступ к native-объектам, запрещает cleartext и microphone, камера ограничена выбранным HTTPS-сервером. Совместимость кнопки/жеста «Назад» реализована новым platform callback на Android 13+ и fallback на Android 8–12.

## Что ещё нужно для публичного выпуска

1. Успешно завершить workflow **Build four platform clients** на GitHub и просмотреть результаты. Наличие workflow само по себе не подтверждает успешную сборку. Если Actions заблокирован настройками/лимитом аккаунта, сборки выполняются на соответствующей системе по инструкциям в папках платформ.
2. Проверить готовые пакеты на Mac, Windows, iPhone/iPad и Android: авторизацию, выход, загрузку из галереи, снимок камерой, отказ в разрешениях, реферальные ссылки и недоступный сервер. Некоторые OAuth-провайдеры ограничивают вход во встроенных браузерах; предусмотрен ввод email-ссылки в том же клиенте.
3. Настроить свой публичный HTTPS-сервер, email/Telegram-провайдеры и подтверждённую учётную запись владельца. Текущий private pilot не становится публичным от установки клиента.
4. Для распространения использовать собственные release-ключи/сертификаты: Android release signing; Apple Team и provisioning для iOS; macOS signing/notarization; Windows code signing при выбранном способе распространения.

Подписанные установщики четырёх платформ, публикация в магазинах, проверка на физических устройствах и production-аудит не заявляются как выполненные.
