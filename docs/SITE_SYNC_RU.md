# Синхронизация Tune Arena с актуальным сайтом

Дата: 11 ноября 2026. Автор: Vadym Tsinderhoz. Версия экспорта: 1.1.0.

Источник web-кода: Sites v33, коммит `3e2b45e7109cb0f831b5114e1e76237fbee66f56`.
База GitHub: `1d9aee85ad4f4de5cfc1d3dae2898ed4138fd30f` (7 ноября 2026).

## Что перенесено

- Лента работ участников, лайки и Турбо, отсутствие дизлайков и рекламной навигации.
- Текущий тур, отдельная видимая карточка следующего тура, раскрываемый список всех туров.
- Победители завершённых публичных туров, призовые места, новый порядок и оформление.
- Гараж: профиль, текущая машина, Premium, рефералы, трофеи; соответствующие рамки аватара и поста.
- Страницы загрузки аватара и машины с постоянными нативными file inputs и обработкой изображений.
- Начальная страница, баннер выставки, Telegram как единственная пользовательская регистрация.
- Удаление своего аккаунта с подтверждением, прекращением сеансов и удалением фотографий; сохранение обезличенных итогов.
- Серверные роли организаторов, модерация, новые модули заказов и трофеев, контракт ERC-721 и связанные тесты. Работа платежей или выпуск NFT не заявляются без отдельной настройки.

## Сохранённые компоненты

Каталоги `android/`, `ios/`, `desktop/`, `macos/`, `windows/`, общая `config/` и готовые файлы `downloads/` сохранены побайтно относительно указанной базы GitHub. Нативные проекты и Android-пакеты в ходе этой синхронизации не пересобирались. Их SHA Git blobs проверяются при подготовке коммита. Дополнительные изменения сделаны только в web, документации, root package/check scripts и workflow web-проверки.

## Адаптации самостоятельного сервера

1. Sites project_id не включён в standalone hosting manifest; D1/R2 bindings сохранены.
2. `TRUST_SITE_AUTH=0` по умолчанию: открытый Worker игнорирует поддельные платформенные заголовки. Режим доверенной Sites-интеграции требует отдельного явного включения.
3. В production регистрация только Telegram OIDC. Владелец самостоятельного сервера определяется по `TUNE_ADMIN_TELEGRAM_ID`, сверяемому с проверенной provider identity; никнейм не даёт прав.
4. DEMO-вход доступен только с development-флагами и localhost. Production и другой origin отвергают этот вход. Безопасный `.dev.vars.example` включён в исходники; реальные секреты не экспортируются.
5. Самостоятельные setup/deploy scripts сохранены и обновлены. Выход завершает текущую cookie-сессию. Удаление аккаунта отзывает все его сеансы и административный доступ.
6. Пять уже существовавших GitHub SQL-миграций и snapshots сохранены без изменения. Добавлены миграции из Sites, затем **0012**: эквивалентный расчёт общего победителя через CTE/window ranking, совместимый с SQLite Workerd. Счёт, границы времени и разрешение ничьей сохранены; исходные данные не изменяются.
7. Локальные миграции выполняются транзакционными D1 batches по Drizzle statement breakpoints через Wrangler `getPlatformProxy`. Это сохраняет SQL-триггеры целиком и использует ту же `.wrangler/state/v3`, что dev server. Повторный запуск пропускает применённые миграции.

Полный список исходных файлов и их Git blob SHA: [SITE_SYNC.json](SITE_SYNC.json). Различия standalone-экспорта перечислены в этом манифесте.
